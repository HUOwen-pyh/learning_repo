# 第 02 晚：NPO、gap 与“不能更好”的语言

## 目标

会严格描述优化问题与判定版本；理解 gap reduction 如何把不可判定的“近似过好”变成复杂度坍塌；区分绝对近似、渐近近似和伪多项式算法。

## 前置回忆（5 分钟）

写出 Vertex-Cover 判定版：“是否存在大小至多 `k` 的覆盖？”思考：若能精确求 OPT，如何回答判定版？反方向为何需对 `k` 二分调用？

## 精读正文（20 分钟）

NPO 问题要求实例和解可多项式编码、可行性与目标值可多项式验证。近似算法解决优化版，不等于“允许判定版答错”。`gap_{a,b}` 的承诺问题只需区分 `OPT<=a` 与 `OPT>b`（最小化）；若从 NP-hard 语言构造实例，使 YES 落在前者、NO 落在后者，那么任何比值 `<b/a` 的算法都能区分两类，因而在 `P!=NP` 假设下不存在。

量词很关键：不可近似阈值常写“对任意 ε>0，不存在 `(c-ε)`-近似，除非……”。条件可能是 `P!=NP`、NP 不含准多项式时间、ETH/Gap-ETH 或 UGC，强弱不可混写。绝对 `α` 保证覆盖全部实例；渐近保证允许 `ALG<=αOPT+β`，小实例的加性常数可很大。伪多项式 `poly(n,W)` 对二进制数值 `W` 并非输入长度 `log W` 的多项式；它却常是 FPTAS 的起点。

代码以 Set Cover 的精确 DP 和贪心作“gap 观察器”：对拍只能显示某分布上的经验 gap，永远不能证明复杂度下界。反例：测试一万随机实例都接近 1，也不能推出最坏比值；坏例可能是精心构造且概率极低。

## 代码实验

`practice.py` 枚举子集 DP 求 OPT，与贪心对拍并输出经验 gap。将集合数增加会看到 `2^m` oracle 爆炸，而贪心仍快；这正是“验证工具”和“算法”的边界。
