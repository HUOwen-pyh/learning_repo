# 第 01 晚：把“差不多好”写成定理

## 目标

把自然语言问题写成 NPO 三元组（实例、可行解、目标值）；分清最小化与最大化的近似比；用精确小实例 oracle 检查实现，但不把 oracle 混进算法复杂度。

## 前置回忆（5 分钟）

回忆 `P`、`NP`、多项式时间和大 O。对图 `G=(V,E)`，顶点覆盖 `C` 满足每条边至少一个端点在 `C`。先想：空图和孤立点会怎样？

## 精读正文（20 分钟）

最小化问题的 `α`-近似要求每个实例上 `cost(A(I)) <= α·OPT(I)`，`α>=1`；最大化常写 `value(A(I)) >= ρ·OPT(I)`，`0<ρ<=1`，也可统一写 `OPT/A <= α`。保证是最坏情况的逐实例量词，不是平均跑得好。

证明通常有三件事：①输出可行；②算法多项式；③找一个可计算下界 `LB<=OPT`（最大化则找上界），再证 `ALG<=α·LB`。顶点覆盖中，任一匹配的边互不共享端点，覆盖每条匹配边至少选一个不同顶点，所以 `|M|<=OPT`；若 `M` 极大，取其全部端点 `C`，否则一条未覆盖边可加入 `M`，与极大性矛盾。因此 `|C|=2|M|<=2OPT`。

“精确值对拍”只在小 `n` 枚举 `2^n` 个集合，用来发现实现错误；它没有改变近似算法本身 `O(|V|+|E|)` 的时间。反例意识：星图上某些极大匹配端点法取 2 个点而 OPT=1，比值正好 2；若误把“极大 matching”写成“最大 matching”，保证仍对但付出了不必要计算。
