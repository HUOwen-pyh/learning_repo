# 第 1 晚：复杂度模型与实验分析

## 学习目标

- 区分最坏、均摊、期望复杂度，以及输入规模和机器常数。
- 用“计数器 + 计时”验证增长阶，而不是从一次计时下结论。
- 识别 Python 实现细节对理论模型的偏离。

## 前置回忆

先口答：二分查找为什么是对数级？`list.insert(0, x)` 为什么不是常数时间？若输入翻倍，(n\log n) 的运行时间理论上约放大多少？

## 精读正文

复杂度先要声明**成本模型**。RAM 模型把固定字长整数的读取、比较、加法视为单位成本；比较模型只允许通过比较获取次序，因此排序有 \(\Omega(n\log n)\) 下界。Python 整数会随数值变长，列表也是对象引用数组，所以“单位操作”只是一种有用近似。

分析循环时选能随规模稳定变化的基本操作。例如二分查找的不变量是：若目标存在，它始终在半开区间 `[lo, hi)` 中。一次比较后区间长度至多减半，因此比较次数不超过 \(\lceil\log_2(n+1)\rceil\)。线性查找的最坏比较数为 \(n\)，但若目标位置均匀随机，成功查找的期望约为 \((n+1)/2\)。“平均”必须附带输入分布，否则没有含义。

实验要同时报告规模、重复次数和稳健统计量。计时容易受解释器预热、缓存、调度影响；操作计数更接近算法结构。对数坐标下拟合斜率，或观察 `T(2n)/T(n)`：线性约为 2，二次约为 4，`n log n` 略大于 2。陷阱包括把小规模常数区误认为渐近区、只测有利输入、以及用不同随机样本比较两个版本。
