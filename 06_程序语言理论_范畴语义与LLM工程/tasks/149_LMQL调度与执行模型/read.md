# 第149晚：LMQL 调度与执行模型

## 目标与前置

- 目标：理解查询解释器如何在模板、模型调用、约束和控制流间调度。
- 前置：第148晚、生成器、状态机。

## 阅读导引

把 §4 的 interpreter/head 与 decoder 交互翻译成状态转移：追加确定文本、请求模型延展、更新变量、求值约束。再用 §5.1–§5.2 区分“当前值能否决定真假”与“追加哪些 token 后可能改变结果”。特别记录何时必须等待模型，何时可在本地继续。

## 核心推导

将执行状态写为 S=(pc, env, prompt, budget)。确定步骤只改变 pc/env/prompt；模型步骤消耗 budget 并产生分支。调度器若按固定优先级选择状态，执行可复现；若并行选择，语义结果应与调度顺序解耦，但费用和延迟可能不同。

## 工业联系与事实标签

- [THEOREM] 对无副作用且有限的分支，公平调度最终会访问每个未剪枝状态。
- [EMPIRICAL] 论文的运行时通过约束传播减少无效生成，效果依任务和模型接口而异。
- [INFERENCE] 显式 budget 是生产系统避免隐藏成本失控的必要状态。
- [OPEN] 多提供商、流式取消和动态限流下的最优调度没有通用策略。
