# 第150晚：PICARD 增量解析

## 目标与前置

- 目标：用增量解析器在每个解码步拒绝不可能形成合法程序的 token。
- 前置：上下文无关语法、LLM token 概念。

## 阅读导引

跟踪一个 SQL 前缀，区分“当前已是合法完整串”与“当前虽不完整但仍可延展”。注意 token 可包含多个字符，增量接口必须消费整个 token。

## 核心推导

对语言 L，安全过滤器接受前缀 p 当且仅当存在后缀 s 使 ps∈L。真实解析器常以可达解析状态近似这个存在性问题。越强的语义 guard 剪枝越多，也越依赖数据库 schema。

## 工业联系与事实标签

- [THEOREM] 若过滤器精确识别 Prefix(L)，它不会删除任何 L 中字符串的前缀。
- [EMPIRICAL] PICARD 在论文的文本到 SQL 实验中提升有效 SQL 比率及任务指标；不可外推到所有语法。
- [INFERENCE] 将 schema guard 作为独立层，能把语法正确与业务授权分开审计。
- [OPEN] 子词切分与高阶语义约束结合时，低延迟精确过滤仍是工程难点。
